# Test Cases: Fake Store API — Products

## TC-PROD-001

| Поле | Значение |
|---|---|
| **ID** | TC-PROD-001 |
| **Заголовок** | Успешное получение списка всех продуктов через GET /products |
| **Предварительные условия** | API-сервис fakestoreapi.com доступен и работает |
| **Окружение** | Postman, fakestoreapi.com, Windows 11 |
| **Постусловия** | Никаких действий не требуется — запрос был выполнен только на чтение (GET), состояние системы не изменилось |
| **Шаги** | 1. Открыть Postman.<br>2. Нажать "+" ("Add request").<br>3. Выбрать метод GET.<br>4. В поле URL вставить запрос `https://fakestoreapi.com/products`.<br>5. Нажать Send.<br>6. Изучить полученный ответ (код состояния, тело ответа, заголовки). |
| **Ожидаемый результат** | Сервер возвращает ответ с кодом 200. Тело ответа содержит массив из 20 продуктов (в соответствии с документацией). Каждый продукт содержит все ожидаемые поля (id, title, price, description, category, image) правильных типов. Заголовок ответа Content-Type — application/json. |
| **Статус** | Passed |
| **Фактический результат** | Результат в целом соответствует ожидаемому. Дополнительно обнаружено: ответ содержит недокументированное поле `rating`, отсутствующее в схеме документации API (см. BUG-001). |

## TC-PROD-003

| Поле | Значение |
|---|---|
| **ID** | TC-PROD-003 |
| **Заголовок** | Успешное добавление нового продукта через запрос к POST /products |
| **Предварительные условия** | API-сервис fakestoreapi.com доступен и работает |

В теле запроса (Body → raw → JSON) указать данные нового продукта, например: `{"title": "Test Product", "price": 19.99, "description": "Test description", "category": "test", "image": "https://example.com/image.jpg"}`.<br>6. Нажать Send.<br>7. Изучить полученный ответ (код состояния, тело ответа, заголовки). |
| **Ожидаемый результат** | Сервер возвращает ответ с кодом 201. Тело ответа содержит созданный продукт, который содержит все ожидаемые поля (id, title, price, description, category, image) правильных типов. Поле id не должно совпадать с уже существующими id других продуктов. Заголовок ответа Content-Type — application/json. |
| **Статус** | Passed |
| **Фактический результат** | Результат соответствует ожидаемому. |

## TC-PROD-004

| Поле | Значение |
|---|---|
| **ID** | TC-PROD-004 |
| **Заголовок** | Создание продукта через POST /products без обязательного поля "title" |
| **Предварительные условия** | API-сервис fakestoreapi.com доступен и работает |
| **Окружение** | Postman, fakestoreapi.com, Windows 11 |
| **Постусловия** | Несмотря на успешный ответ (201 Created) с присвоением id, созданный продукт фактически не сохраняется на сервере — повторный запрос GET /products/21 не находит этот продукт. Это особенность тестового API, не позволяющего реально изменять состояние данных. Реальная очистка тестовых данных не требуется. |
| **Шаги** | 1. Открыть Postman.<br>2. Нажать "+" ("Add request").<br>3. Выбрать метод POST.<br>4. В поле URL вставить запрос `https://fakestoreapi.com/products`.<br>5. В теле запроса (Body → raw → JSON) указать данные нового продукта, например: `{"price": 19.99, "description": "Test description", "category": "test", "image": "https://example.com/image.jpg"}`.<br>6. Нажать Send.<br>7. Изучить полученный ответ (код состояния, тело ответа, заголовки). |
| **Ожидаемый результат** | Возможны два варианта: (1) сервер возвращает код 400 (Bad Request) с сообщением об ошибке, если title является обязательным полем; (2) сервер возвращает код 201 (Created) и создаёт продукт без значения в поле title (title отсутствует/пустая строка/null). В этом случае тело ответа содержит остальные поля (id, price, description, category, image) правильных типов, а поле id не совпадает с уже существующими id других продуктов. Content-Type — application/json. |
| **Статус** | Passed |
| **Фактический результат** | Результат соответствует второму варианту, продукт создался без поля title. |
